# AutoClip v1.1.1: native-resolution download hotfix

Remote downloads select the highest exposed native resolution, then frame rate,
instead of applying the former 1080p/MP4 preference. Saved settings using the
exact old default migrate automatically; deliberate custom selectors remain
intact. Original media, existing clips and export canvas/encoder settings are
preserved. Better source quality requires a subsequent download.

Twitch may expose 1440p only to a signed-in session. Settings now labels the
browser-cookie option for YouTube and Twitch. Choose the browser where you are
signed into Twitch and close that browser before downloading. This release
cannot select a format that the provider does not expose to the configured
session. No authenticated full 1440p VOD download is claimed.

## Installation and compatibility

Fresh machines use [AutoClip-Setup-v1.1.1.exe](https://github.com/Farkoal2128/AutoClip-MVP/releases/download/v1.1.1/AutoClip-Setup-v1.1.1.exe), which installs v1.1.1 directly. See the full-installer evidence below.

Existing v1.0.0/MVP installations download `AutoClip-Update-v1.1.1.zip`, finish/cancel work, quit AutoClip, extract
the ZIP and follow `UPDATE.md`. It supplies the manifest and wheel explicitly
to the untouched installed updater. Supports exact v1.0.0 and MVP r1 runtime
identities, including v1.1.0 application layers. Rollback retains the preceding
app layer. The original app-only ZIP remains bound to those older runtimes; new v1.1.1 installations do not need it.

The initial app-only publication shipped no new installer or native components. The subsequent full installer repackages the same app and qualified components with a new runtime identity and matching updater pins.
Root `install.ps1` and `app-release.json` keep their existing v1.0.0 bytes for
installed immutable pin compatibility. The update ZIP is the v1.1.1 delivery
route; the root feed does not automatically discover this app layer.
