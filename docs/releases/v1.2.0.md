# AutoClip v1.2.0 — safety and reliability fixes

Fresh installations: download **[AutoClip-Setup-v1.2.0.exe](https://github.com/Farkoal2128/AutoClip-MVP/releases/download/v1.2.0/AutoClip-Setup-v1.2.0.exe)**. Setup installs app **1.2.0 directly** and includes matching maintenance/updater pins.

Existing v1.1.1, v1.0.0 or MVP r1 installations: finish/cancel work, quit AutoClip, download **[AutoClip-Update-v1.2.0.zip](https://github.com/Farkoal2128/AutoClip-MVP/releases/download/v1.2.0/AutoClip-Update-v1.2.0.zip)**, and follow its `UPDATE.md`. The ZIP uses your unchanged installed updater with explicit manifest/wheel inputs and retains the previous app for rollback. Original media and saved clip edits are preserved.

## Fixes

1. **Frontend file containment:** encoded traversal paths cannot read files outside the resolved bundled frontend directory.
2. **Safe storage relocation:** downloads, pipeline work, exports, preview/chat preparation, file responses and cleanup exclude storage moves. New activity receives a retryable conflict during a move. Surviving native workers retain protection after request cancellation, preventing late writes from being deleted with the old storage tree.
3. **Correct clip-caption ownership:** switching clips clears prior words immediately. Late responses for the previous selection are ignored. Editing stays disabled while loading or after a failed read, and failed reads have a retry button.
4. **Concurrent render isolation:** matching export filenames no longer share captions or chat-render assets when their full destinations differ.
5. **Queue recovery:** filesystem/setup failures mark the affected job failed, clear running state, and leave the worker available for subsequent jobs.
6. **Provider validation:** invalid provider edits are rejected before persistence, preserving readable settings.
7. **Local request authority:** untrusted Host and Origin headers are rejected before side effects. localhost, loopback IPv4/IPv6, local development browser origins and Origin-less local CLI requests remain usable. Non-loopback browser access is intentionally rejected.
8. **Frontend regression checks:** all frontend behavioral tests now run in CI and the full local verification command.
9. **Shared media formats:** ingest and storage recovery use the same accepted-format set.

Retains v1.1.1 native-resolution downloads and v1.1.0 browser codec compatibility. Native dependency archives are unchanged; CPU is the default installation profile, and NVIDIA retains its existing qualification/prerequisite scope.

`SHA256SUMS`, `package-provenance.json`, the Setup receipt and validation records identify the exact assets. Historical releases and root compatibility feeds remain available and unchanged. Follow the update ZIP instructions for older installations instead of replacing receipt-bound helpers.

Storage coordination applies within a single server process. Local installer tests use this existing Windows host and pinned cached prerequisites; they do not establish clean-machine/VM coverage, GUI Finish-launch behavior or fresh NVIDIA inference.
